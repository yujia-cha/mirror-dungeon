# 거울 던전 루트 플래너

림버스 컴퍼니 **거울 던전**에서 쓰려는 덱과 원하는 E.G.O 기프트를 고르면, 그 기프트를 모으기 위한 **층별 테마팩 루트**를 계산해 주는 웹 도구입니다.

거울 던전의 기프트는 어느 팩에서나 나오는 범용 드랍과 특정 테마팩에서만 나오는 전용 기프트로 갈리고, 일부는 서로 다른 팩에서 얻은 재료를 조합해야 합니다. 게다가 테마팩은 정해진 층에서만 등장합니다. 그래서 "이 기프트들을 원한다"가 정해지면 **어느 층에서 어느 팩에 들어가야 하는지**가 따라 정해집니다. 이 도구가 그 계산을 합니다.

## 무엇을 해 주나

- 덱(인격 12인)을 고르거나 게임의 **편성 코드**를 붙여넣어 불러오기
- 목표 기프트 정하기 — 키워드·조건·등급·죄악으로 필터, 조건부 기프트는 **내 덱이 조건을 충족하는지** 바로 표시
- 층별 루트 제시 — 각 층에 들어갈 테마팩과 그 팩에서 챌 기프트, 시작 기프트, 그리고 **어떤 기프트를 관측하면 루트가 유연해지는지**(관측 추천)
- 불가능한 요구는 이유와 함께 알려줌 (그 층 범위에 팩이 없음 / 전용 기프트끼리 층이 충돌 / 덱이 조건을 못 채움). 팩이 충돌하면 결정 카드가 어느 기프트를 목표에서 빼면 무엇을 획득하고 어느 팩이 들어오는지 한 줄씩 보여줌
- 계산 결과를 URL로 공유

## 쓰는 법

배포된 사이트(https://yujia-cha.github.io/mirror-dungeon/)를 열면 바로 런 화면입니다. 가운데 무대에 지금 층과 들어갈 수 있는 테마팩이 있고, 왼쪽 패널(`≡ 덱`)에서 덱과 원하는 기프트를 고르고, 오른쪽 패널(`≡ 전체 루트`)에서 전체 루트·목표·추적기를 봅니다. 모바일에서는 두 패널이 각각 전체 화면 페이지로 열립니다.

### 1. 덱

- **덱 탭**에서 수감자 칸을 눌러 인격을 고르거나, 게임의 **편성 코드**를 「코드 가져오기」에 붙여 넣습니다. 코드에 출격 순서가 있으면 그대로 따릅니다.
- 조건부 기프트(「출격 인원 중 화상 부여 스킬 3개 이상」 같은 것)는 대부분 **출격한 인격**만 셉니다. 칸의 「대기」 체크를 켜서 출격 인원을 정해 두어야 조건 판정이 맞습니다.
- 덱 아래 칩(「화상 2/5」)은 출격 인원 / 편성 전체의 스킬 수입니다.

### 2. 기프트

- **기프트 탭**의 타일 격자에서 목표로 삼을 기프트를 누릅니다(아이콘을 누르면 목표에 추가, 이름을 누르면 상세). 탭에는 **「지금 덱으로 활성」**(내 덱이 조건을 채우는 기프트)만 있고, 기본으로 **「목표가 아닌 것만 보기」**가 켜져 있어 이미 목표인 것은 숨습니다(체크를 끄면 모두 보입니다). 나머지 기프트는 검색으로 찾습니다 — 검색은 전체 기프트에서, 부분 문자열로, 초성만 치면 초성 검색입니다.
- 검색창 오른쪽 끝의 **`>>`(모두 보기)**는 전체 기프트를 넓은 격자로 엽니다(데스크톱은 가운데 무대 자리, 휴대폰은 새 페이지). 열려 있는 동안 같은 버튼이 **`<<`**로 바뀌어 누르면 다시 무대로 돌아옵니다. 탭에 친 검색어를 그대로 가져가며, 필터(키워드·조건·등급·죄악)는 여기에 있습니다. 「조건」 필터의 **「조건 없음」**은 덱이 판정할 조건이 없는 기프트만 남깁니다(편성 수에 따라 강화되는 것과 완전 공명 조건은 덱 조건이 아닙니다).
- 타일의 **바깥 링**이 조건 판정입니다(초록 충족 · 빨강 미충족 · 회색 조건 없음). 우하 배지는 키워드입니다.
- 조합으로만 나오는 기프트를 고르면 재료까지 루트가 모으러 갑니다. 상세 시트의 「재료도 목표」를 끄면 결과만 목표로 둡니다. 조합식의 재료를 누르면 그 기프트의 설명으로 넘어가고, 맨 위 「←」로 돌아옵니다.
- **시작 키워드**는 탭 맨 아래에 있습니다. 「자동」은 고른 기프트를 따라, 시작 기프트 풀에 목표가 든 키워드를 고릅니다(그런 풀이 없으면 덱의 주 키워드). 그 아래 한 줄이 어떤 시작 기프트를 받는지, 혹은 목표와 상관이 없어 아무 키워드나 골라도 되는지 알려 줍니다.
- **관측**: 검색창 아래 슬롯(최대 3칸)에 기프트를 넣으면 「관측 지정」으로 「기프트 관측」에서 받습니다. 조합 결과는 관측할 수 없으므로 조합에 관측을 쓰려면 **재료**를 넣습니다. 관측은 1층을 떠나기 전까지만 바꿀 수 있습니다.

### 3. 루트

- 오른쪽 **전체 루트**가 층별 테마팩을 노선도로 그립니다. 요약의 「획득 M/T」는 목표 기프트 중 루트가 가져다주는 수이고, 「범용 드랍 N」은 팩이 아니라 **어느 팩에서나 나올 수 있는** 것으로 세운 수입니다(반드시 나오지는 않습니다 — 상점·새로고침을 함께 쓰세요).
- **전부 얻을 수 없으면** 요약 아래에 「…중 하나를 목표에서 빼야 합니다」 카드가 뜹니다. 어떤 기프트를 목표에서 빼면 몇 개를 획득하고 어느 팩이 대신 들어오는지 한 줄씩 보여 주고, 행의 ✕는 「목표에서 빼기」, 경로 아이콘은 그 루트를 미리 보여 줍니다(노선도로 스크롤합니다).
- **미해결** 카드는 루트가 해결하지 못한 기프트와 이유(층 범위 밖·팩 충돌·재료 미해결·팩 경로 없음 …)를 적고, 관측으로 풀 수 있으면 버튼을 냅니다.
- 오른쪽 위의 복사 버튼이 루트를 글로 복사합니다(폰 메모용).

### 4. 런

- 무대의 팩 카드에서 **입장**하면(버튼 또는 카드를 아래로 당기기) 그 팩에서 챙길 기프트 타일이 나옵니다. **얻은 것은 아이콘을 눌러 획득 표시**하세요(이름을 누르면 상세) — 표시하지 않고 층을 떠나면 「미획득」으로 기록됩니다. 미획득은 「그 팩에서 못 얻음」이라, 다른 팩이 주는 기프트는 남은 층에서 다시 루팅되고, 그 팩에서만 나오는 기프트는 이 런에서 끝입니다.
- 「다음 층」(또는 아래로 당기기)으로 넘어가고, 「입장 취소」(위로 당기기)는 입장을 취소하며 그 팩에서 표시한 것을 지웁니다. 층 스트립을 눌러 지난 층을 다시 볼 수 있습니다.
- 루트는 현재 층부터 다시 계산됩니다. 계획에 없는 팩에 들어가도 됩니다.
- **⋯ 메뉴**의 「링크 복사」가 덱·목표·설정을 담은 공유 링크를 만듭니다(런 진행은 담지 않습니다). 「초기화」는 덱을 기본 LCB 수감자로, 목표·설정·런을 처음으로 되돌립니다.

로컬에서 돌리려면:

```bash
npm ci
npm run data:build   # 동봉된 원본 데이터로 게임 데이터 생성
npm run dev
```

## 개발

```bash
npm run check        # lint + typecheck + test + 데이터 검증
npm test             # 단위 테스트
npm run route -- --deck 10101,10203 --want 9088 --floors 1-5 --difficulty hard
```

루트가 어떻게 계산되는지는 [`docs/route-algorithm.md`](docs/route-algorithm.md)에 단계별로 적어 두었습니다. 게임 데이터의 출처와 가공 방식은 [`data/README.md`](data/README.md)에 있습니다. 설계 규칙과 마일스톤별 변경 기록은 개발 저장소의 `CLAUDE.md`·`docs/design/`·`docs/review/`·`docs/research/`에 있습니다.

## 데이터와 권리

게임 데이터·텍스트·이미지의 권리는 **Project Moon**에 있습니다. 이 저장소는 비상업 팬 프로젝트이며 Project Moon과 제휴하거나 승인받지 않았습니다.

플래너가 동작하는 데 필요한 범위의 게임 데이터를 세 곳에서 가져옵니다 — [LEAGUE-OF-NINE/OpenLethe](https://github.com/LEAGUE-OF-NINE/OpenLethe) (클라이언트 정적 데이터), [x1bViolet/Limbus-Localization-Files](https://github.com/x1bViolet/Limbus-Localization-Files) (공식 한국어·영어 현지화 원문), [eldritchtools/limbus-assets](https://github.com/eldritchtools/limbus-assets) (정적 데이터에 없는 인격을 채우는 가공 데이터). 어떤 파일을 어디서 가져오는지는 [`data/README.md`](data/README.md)와 [`data/sources.lock.json`](data/sources.lock.json)에 있습니다.

게임 이미지는 이 저장소에 담지 않습니다.
